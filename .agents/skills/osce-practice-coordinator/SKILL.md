# OSCE idea 到語音練習

預設對象是醫學系實習醫學生；以病史詢問或醫病溝通、形成性練習為第一版範圍。使用者指定的對象、時間及格式優先。

## 接收與分流

- 新 idea：重用已提供設定。只補問會改變教案方向的站型、目標及情境；每次最多三題，給可選預設。若學生不會設定，提出兩個可完成的小情境。
- 已有完整教案：先檢查考生指引、病人事實、資訊揭露規則及評分錨點，補齊缺漏再包裝；不得另編相衝突的答案。
- 已有演練包且要開始：交給 `$osce-standardized-patient`，不再跑出題訪談。
- 已有逐字稿且要回饋：交給 `$osce-practice-feedback`。

預設使用「考前練習」，只顯示考生指引；學生若要看完整教案，改為「出題學習」。學生看過答案後仍可練習，但記錄為已知題；不能稱為盲測。語音演練包可被持有人閱讀，不是保密儲存。

## 設計與教案

若環境有 OSCE 命題技能，可依其與教師規範協助設計；也可直接依本公開版 [rules.practice.yaml](../../../rules.practice.yaml) 與以下流程產生文字教案。此規則快照是教學設計預設，並非已核對的最新國考規範。

沿用其藍圖、五大部分、0/1/2 錨點及 SP 提問限制。沒有另行指定時建議 8 分鐘、15 項 30 分；把採用設定寫在藍圖。完整授權直接製作時不另加確認停點。先確認內容。若需要正式格式 Word，使用自己可存取的產檔工具或手動轉檔，並逐頁目視檢查；本公開版的匯出工具不產生 Word。

虛構病例明示為虛構，病例值由情境設計產生，不冒充觀察資料。臨床知識與建議查可靠來源，標明覆核日；教師未審閱不稱為正式考題或已驗證評量工具。

## 交換格式與輸出

需要匯出時讀 [病例格式](references/case-format.md)。維護一個 `case.json` 為該題內容來源；對應 JSON Schema 見 [case.schema.json](references/case.schema.json)。由它產生：

1. `考生指引.md`：只有角色、情境、任務、時間與允許取得資料。
2. `完整教案.md`：藍圖、五大部分、SP 對白、錨點、場地配置、來源及驗證狀態。
3. `語音演練包.txt`：自含 SP 規則、回饋規則及完整病例資料。不同平台讀取後不需安裝技能。
4. `教案內容.yaml`：供相容的教案產檔工具使用的內容格式。

使用本技能的 [scripts/package_case.py](scripts/package_case.py)：

```text
python .agents/skills/osce-practice-coordinator/scripts/package_case.py examples/HX-001/case.json --rules rules.practice.yaml --out new-output
```

此工具需 PyYAML、jsonschema；不連網、不呼叫模型、不自動啟動語音、不覆寫既有輸出。它會從相鄰 `osce-standardized-patient/assets/` 與 `osce-practice-feedback/assets/` 讀取執行指令；分發時三個新技能應放在同一層。

## 網頁語音交接

讓學生上傳單一演練包，輸入「請依附件載入本站，只顯示考生指引，確認可開始後等待我。」讀取成功後，在同一個聊天中由學生開啟語音，說「開始演練」。不能承諾每個帳號均有相同語音或上傳功能；附件讀不到則改貼 TXT 內容，不能假稱已載入。

使用外部計時器。先在文字或語音中詢問「目前是準備、演練、暫停還是回饋狀態？」可檢查交接；此查詢只回狀態、不洩題。個案資料若在切換後缺失，暫停並重新載入，不能重編病人。

## 驗證與收尾

檢查病例一致、分數加總、SP 回應映射、候選資料無答案、引用可查，以及跨平台指令自含。記錄四種狀態：結構檢核、AI 文字演練、真人語音實測、教師審閱；四者不可相互代替。更新既有專案狀態及 handoff，不把一般練習分數寫成研究 RESULTS_LOCK。
